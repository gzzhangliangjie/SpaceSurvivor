> 分析范围：`Assets/DOTSSurvivors/` 全部脚本与资产结构

## 1. 项目概览

| 项 | 内容 |
|------|------|
| 类型 | 太空主题生存类游戏（Survivors-like） |
| 引擎 | Unity 6（6000.0.30f1），URP 渲染管线 |
| 核心技术 | Entities 1.0+（ECS）、Burst、Job System、Unity Physics、Input System、TextMeshPro |
| 代码组织 | 单 asmdef：`DOTSSurvivors.asmdef`，所有脚本在同一程序集中 |
| 架构风格 | **ECS 为主 + GameObject 混合**：游戏逻辑跑在 DOTS 世界，UI/音频/VFX 走 MonoBehaviour，两者通过事件桥接 |

### 规模统计

- 脚本总数：约 **150 个 .cs 文件**（不含编辑器扩展 2 个）
- ECS System：约 **86 个**（80 个 `ISystem`/Burst 编译 + 6 个 `SystemBase` 托管系统）
- Authoring/Baker：**89 个** Baker
- UI 控制器：21 个 MonoBehaviour
- 场景：`TitleScene` + 3 个关卡（Mars / Moon / Venus）
- 配置 SO：7 类（CharacterProperties、EnemySpawnEvents/Waves、BonusItem、RandomItemDrop、SpaceAgency、StageProperties）

## 2. 总体架构

```
┌────────────────────────── GameObject 世界（托管） ──────────────────────────┐
│  UI/*（21 个控制器）   SFX/*（音频）   VFX/*（动画/粒子）   General（暂停/存档） │
│        ▲                    ▲                  ▲                            │
│        └──────── C# 事件订阅（System 上公开的 Action）────────┘              │
├────────────────────────────── 事件桥 ───────────────────────────────────────┤
│  DOTS 世界（Burst 编译，零 GC）                                              │
│  GameEntity（单例）→ 玩家/敌人/投射物/物品 → EntityInteraction 缓冲区         │
└─────────────────────────────────────────────────────────────────────────────┘
```

**关键设计决策：**

1. **SystemBase 只出现在"必须托管"的地方**——`GlobalTimeUpdateSystem`、`BeginGameOverSystem`、`PlayerAuthoring` 内的初始化系统、物品拾取给钱等需要与 GameObject/托管 API 交互的系统。其余全部为 `ISystem` + `[BurstCompile]`。
2. **托管数据集中在 `ManagedGameData`（GameEntity 上的 class IComponentData）**，存放武器/敌人 prefab 的 `Dictionary<enum, Entity>` 查找表、UI Canvas prefab 等。系统需要时通过 `GameEntityTag` 单例实体取用。
3. **ScriptableObject 是唯一配置来源**，Baker 在烘焙期读 SO 数据写入组件，运行时 ECS 世界不持有 SO 引用。

## 4. 核心机制详解

### 4.1 系统组（DS_SystemGroups.cs）——一帧的执行顺序

项目自定义了 7 个系统组，严格编排每帧逻辑：

```
InitializationSystemGroup
└── DS_InitializationSystemGroup（帧首初始化：EntityRandom、相机、生成器初始化等）

SimulationSystemGroup
├── DS_AttackSystemGroup          ← 所有武器攻击逻辑（先于位移/交互）
├── DS_TranslationSystemGroup     ← 所有 LocalTransform 移动系统
│   └──（随后的 TransformSystemGroup 将位移写入 LocalToWorld 供渲染）
├── DS_InteractionSystemGroup     ← 实体交互处理（碰撞响应、伤害结算、拾取）
├── DS_EffectsSystemGroup（帧末）  ← 视觉/音频效果触发
└── DS_DestructionSystemGroup（帧末）← 统一销毁（保证效果先播放）

PhysicsSystemGroup（FixedStep）
└── DS_PhysicsSystemGroup         ← 物理模拟之后、消费触发/碰撞事件与重叠查询
```

**约定**：新增系统的 `[UpdateInGroup]` 必须归入对应 DS 组，而不是裸挂在 SimulationSystemGroup 下。

### 4.2 EntityInteraction 交互框架（全项目的中枢设计）

这是理解本项目最重要的一块（见 `General/EntityInteractionAuthoring.cs` 的长注释）：

- `EntityInteraction : IBufferElementData` 动态缓冲区挂在可交互实体上（通常由 `EntityInteractionAuthoring` 以 `[RequireComponent]` 形式附加）。
- **产生交互**：触发事件 Job / 定时逻辑向一方缓冲区写入 `IsHandled=false + TargetEntity`。
- **消费交互**：各种交互系统（`DealHitPointsOnInteractionSystem`、`HealOnInteractionSystem`、`KnockbackOnInteractionSystem`…）扫描未处理条目并执行行为。
- **帧末结算**：`HandleEntityInteractionSystem`（DS_InteractionSystemGroup 末尾）把所有条目标记 `IsHandled=true`；缓冲区**不清空**，用于去重（同一对实体持续重叠只触发一次）。

好处：解耦了"谁碰到谁"与"碰到后发生什么"——伤害、治疗、反弹、音效、自毁都可以独立增删，不需要改碰撞代码。

### 4.3 Authoring + Baker 模式（89 个 Baker 的统一写法）

典型文件是"四合一"结构：**Tag 组件 + 数据组件 + Authoring MonoBehaviour + Baker**，如 `LinearMovementAuthoring.cs`：

```
LinearMovementTag / LinearMovementData (IComponentData)
  ↑ Bake()
LinearMovementAuthoring : MonoBehaviour（Inspector 配置）
  → LinearMovementSystem : ISystem（DS_TranslationSystemGroup 中移动）
```

几乎每个行为都是"数据组件 + 一个消费系统"的正交组合，实体通过组件拼装获得行为（组合优于继承的典型实践）。

### 4.4 武器体系（PlayerAttacks，12 种武器）

结构高度模板化，每种武器两个文件：

| 文件 | 内容 |
|------|------|
| `XxxWeaponAuthoring.cs` | 武器升级配置 + 攻击系统（`XxxAttackSystem`，负责按冷却生成攻击实体） |
| `XxxEntityAuthoring.cs` | 攻击实体本体（移动、命中、特效、自毁等组件拼装） |

- `WeaponAuthoring.cs` / `WeaponUpgradeProperties.cs`：升级等级与数值。
- `CapabilityUpgradeController`（托管单例）：管理玩家拥有的武器/被动、升级选择事件，是 UI 与 ECS 之间的枢纽。
- 武器清单：Laser、SawBlade、Rocket(RadioactiveWaste)、PlasmaBlast、BlackHole、CO2Cloud、Drone、Satellite、Jetpack、OxygenHose、Wrench、Screwdriver。

### 4.5 属性修改器（StatModifiers）

- `StatModifierController`（DontDestroyOnLoad 单例）从 `Resources/ScriptableObjects/StatModifierProperties` 加载全部修改器定义，并创建 `CharacterDefaultModificationValues` 单例实体（12 种属性：伤害、攻速、移速、吸引半径、经验加成等）。
- `StatModifier : IBufferElementData`（容量 12）缓冲在角色的 active stat 实体上，`RecalculateStatsSystem` 汇总计算最终属性。
- 计算 类型（`StatModifierCalculationType`）分四档：AbsoluteInteger / AbsoluteDecimal / IncreasingInteger / Percentage，UI 显示逻辑随类型不同。

### 4.6 敌人与波次生成（EnemyLogic）

- `EnemySpawnAuthoring`（701 行，最大文件之一）：按 `EnemySpawnWaveProperties → EnemySpawnEventProperties → EnemyType` 三级配置，支持编队（`SpawnFormation`）。
- 运行时由 `EnemySpawnSystem` / `EnemyWaveSystem` 读取 `GameTime` 单例驱动波次；跨波清理由 `DestroyPreviousWaveEnemySystem` 处理。
- 敌人移动是三种正交组件：线性（EnemyLinearMovement）、追玩家（EnemyMoveToPlayer）、正弦波（EnemySineWaveMovement），与普通实体共用 `Transformations` 库。

### 4.7 销毁体系（Destruction）

15 个文件构成"销毁策略库"，全部最终汇入 `DS_DestructionSystemGroup`：

- 按条件：`DestroyAfterTime`、`DestroyAfterNumberHits`、`DestroyAtPosition`、`DestroyOffCamera`、`DestroyOnEnvironmentContact`、`InstantDestroyOnInteraction`
- 副作用：`DropExperienceOnDestroy`、`SpawnOnDestroy`、`SpawnRandomOnDestroy`（掉落 `RandomItemDropProperties`）
- `DestroyEntitySystem` 统一执行，保证销毁前效果系统已跑完。

## 5. ECS ↔ MonoBehaviour 桥接模式

项目有三种固定桥接手法，新增功能时应沿用：

| 模式 | 实现 | 示例 |
|------|------|------|
| **系统公开 C# 事件** | SystemBase 声明 `event Action<T>`，UI 控制器在协程中等待 `World.DefaultGameObjectInjectionWorld` 就绪后订阅 | `HandlePlayerExperienceThisFrameSystem.OnUpdatePlayerLevel` → `HUDUIController` |
| **托管单例控制器** | GameObject 侧单例持有配置/状态，ECS 侧按需创建数据实体 | `CapabilityUpgradeController`、`StatModifierController`、`PersistentDataManager`（PlayerPrefs 存档） |
| **Companion GameObject** | Authoring 挂 GameObject，`UpdateCompanionGameObjectSystem` 每帧同步实体位置 | `CompanionGameObjectAuthoring`、世界空间血条 `PlayerWorldUISystem`、拖尾 `JetpackTrailRendererController` |

UI 细节：订阅失败保护（最多重试 600 帧后报错）、OnEnable/OnDisable 成对订阅退订、F2 切换 HUD 隐藏。

## 6. 场景与游戏流程

```
TitleScene（角色选择 CharacterSelectPanel + 关卡选择 StageSelectPanel）
   │  选择 CharacterProperties / StageProperties（SO）
   ▼
MarsLevel / MoonLevel / VenusLevel
   ├─ GameEntity（单例）：GameEntityPrefabs、ManagedGameData、GameTime、
   │   AliensDefeatedCount、CoinsCollected
   ├─ GameStartSystem 消费 InitializeGameTag → 生成玩家、移除 Tag（只跑一次）
   ├─ LevelGenerationSystem 程序化铺装饰物（LevelGenerationAuthoring）
   ├─ 敌人波次 → 玩家攻击 → 交互结算 → 掉落/拾取 → 升级循环
   └─ BeginGameOverSystem（SystemBase）→ 结算 ResultsPanel
```

跨场景持久层：`PersistentDataManager`（选中的角色/关卡/金币）+ `StatModifierController`，均 DontDestroyOnLoad。

## 7. 值得注意的代码事实（改进候选）

1. **`DOTSSurvivorsInputActions.cs`（1385 行）**：Input System 自动生成代码，手改会被覆盖——改动应通过 `.inputactions` 资产重新生成。
2. **SystemAPI.Query 全量扫描模式**：交互系统逐实体扫缓冲区（如 `HandleEntityInteractionSystem`），实体量大时是潜在热点，可考虑 `IJobChunk`。
3. **托管/非托管边界靠约定维持**：`ManagedGameData` 是唯一豁免点，新增托管引用应集中到这里而不是散落新组件。
4. **`ClampModificationValue` 依赖 `StatModifierController.Instance`**：托管单例被非托管辅助扩展调用，注意初始化顺序（Awake 时已加载，安全，但测试中会 NRE）。
5. **注释质量很高**：关键类（EntityInteraction、DS_SystemGroups、StatModifier）均有中文/英文双语 XML 文档说明设计意图——新代码应保持这一水准。
